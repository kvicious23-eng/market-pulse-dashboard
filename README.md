## 수집과 게시의 완료 조건

1. 현재 활성 목록, 상품 식별자, 회차, 요청·실행 ID, 시작 증거와 완료 JSON을 대조한다.
2. Windows와 브라우저의 마감시각 동일성은 UTC 정수 초까지만 비교한다. 원본 시각과 실제 만료 기한은 보존한다.
3. 회차 무결성 오류는 전체 게시를 차단한다. 모델별 수집 오류는 기존 가격을 참고값으로만 남기고 파란 재확인 상태로 격리한다.
4. SRP는 현재 관리 목록의 수기 값만 사용한다. 사용자가 지운 SRP를 오래된 수집본에서 되살리지 않는다.
5. 상품페이지는 기준가격·카드 혜택, 주문서는 일반쿠폰·와우 즉시·와우 쿠폰의 근거다. 현재 운영 규칙상 주문서 쿠폰 합계를 상품페이지 현재 가격과 강제로 일치시키지 않는다.
6. Git 커밋·푸시, GitHub 검사, Pages 성공과 실제 공개 데이터 일치를 각각 확인한다. 코드 배포 성공을 가격 데이터 갱신 성공으로 해석하지 않는다.

가격 게시와 재고 합계 전용 게시 모두 공유 저장소 잠금과 게시 복구 기록을 사용한다. 커밋 전 실패는 소유한 출력만 복구하고, 검증된 커밋 이후 푸시 실패는 커밋을 보존해 재전송한다. 가격·경쟁 이력은 같은 회차 재실행으로 중복 누적하지 않는다.

## 브랜드와 로그

- 대시보드: /brand/lenovo/, /brand/acer/, /brand/godox/ 및 저장된 신규 브랜드의 /brand/{slug}/
- 기존 /와 /acer/는 브랜드 URL로 이동한다.
- 상품 추가·삭제·브랜드 변경은 최신 저장 목록과 새 전체 수집을 기준으로 반영하며 과거 이력은 보존한다.
- 로그: reports/scan-watchdog.log, reports/scheduled-upload.log, reports/blue-recovery.log, reports/supplier-daily-upload.log
- 요청이 아직 없으면 원래 기한 안에서 기다린다. 존재하는 요청 파일의 손상이나 회차 불일치는 보존하고 명확한 오류로 종료하며 새 ID로 덮어쓰지 않는다.
- Windows 작업 스케줄러의 LastTaskResult는 해당 예약 실행의 결과다. 별도 수동 복구 성공이 과거 실패 값을 자동으로 지우지는 않는다.

## 업데이트와 검사

운영 소스 변경 전 수집·업로드·복구 비실행과 다음 예약까지의 여유를 확인한다. 가격 확장 소스가 바뀌면 세 브라우저를 각각 재로드한 후 별도 nonce의 verify로 실행 버전·권한·목록·회차 소유권을 확인한다. Windows 코드나 문서만 바뀌면 필요한 검증을 수행하고 불필요한 재로드나 추가 실수집을 시작하지 않는다.

CI는 Ubuntu와 Windows에서 JavaScript LF/CRLF 검사를 수행하고 Windows PowerShell 5.1의 수집·복구·이력·게시·Supplier 검사를 통과한 main만 Pages에 배포한다. Actions 수동 Run workflow는 검증·배포만 수행한다. 가격 수집은 운영 PC의 내 상품/지정 경쟁모델 단계에서 실행한다.

## 지정 쿠팡 경쟁모델

상품관리의 각 내 상품에서 경쟁모델명·쿠팡 URL·메모·활성을 등록한다. 동일 상품·옵션·판매자는 공유 수집하며 미등록도 허용한다. 내 상품 Pages 성공 후 별도 경쟁단계가 원래 예산 안에서 실행된다. SELLER COMPARISON과 Excel은 지정 경쟁모델만 사용하며 다나와·에누리 비교는 폐기했다. 상세 기준은 PROJECT_RULES.md의 1.9.75 절을 따른다.

상품관리 공용 자동수집 목록은 Chrome에서 저장한다. Edge/Whale의 관리 화면 저장은 각각 별도 수동 검증 파일을 사용한다. 여러 관리 탭의 오래된 목록 저장은 최신 기준 대조에서 거부하며, 워커가 설정과 완료된 파일 저장을 직렬화한다. 경쟁 결과 전달 실패 시 가격 재수집 대신 보존된 결과 파일만 재전달한다. 상세 감사는 [PROCESS_AUDIT_2026-11-04.md](PROCESS_AUDIT_2026-11-04.md)를 참고한다.

최신 경계·연결 과정 재감사는 [PROCESS_BOUNDARY_AUDIT_2026-11-04.md](PROCESS_BOUNDARY_AUDIT_2026-11-04.md)를 참고한다. 실행 계보·진단 잠금·숫자/파일 경계의 실제 실패 주입과 격리/자연 운영 증거를 구분한다.
